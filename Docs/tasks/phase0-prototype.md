# フェーズ0：プロトタイプ

## 目的

「使用済みサイクルによって、移動と戦闘のダイスの取り合いが面白くなるか」を、最小の構成で確かめる。見た目は四角と数字だけでよい。絵・音・演出は作らない。

## 合格条件

- スタートからゴールまで遊べる（ゲームオーバーとクリアの両方がある）。
- 遊んだ人が「どのダイスを移動に使うか」で迷う場面が、1プレイに何度もある。
- EditMode テストがすべて通り、コンソールにエラーが出ていない。

## 作るもの

### 盤面

- 直線の20マス（分岐なし）。マス0がスタート、マス20がゴール。
- マスの種類は「空白」「戦闘」「休憩」の3種類。ゴールは「ボス戦」。
- 配置はシード付きでランダム生成：
    - マス1〜3は空白だけ。
    - 戦闘は6個、休憩は3個、残りは空白。
    - 同じ種類のマスは2つまでしか連続しない（空白は3つまで）。
    - マス14〜17のどこかに休憩を1つ必ず置く。
- 出目がゴールを越えても、ゴールで止まる。

### ダイス（3種類）

| ダイス | 面 |
| --- | --- |
| 普通の賽 | 1,2,3,4,5,6 |
| 四五六賽 | 4,4,5,5,6,6 |
| 一二三賽 | 1,1,2,2,3,3 |

- 初期ポーチ：普通の賽×2、四五六賽×1、一二三賽×1。
- ダイスの状態は「使用可能」「使用済み」。移動でも戦闘でも、使ったら使用済み。
- 使用可能が0個になった瞬間に全部が使用可能に戻る（リフレッシュ）。戦闘中でも同じ。
- 戦闘で使ったダイスは、戦闘のあとも使用済みのまま残る。

### プレイヤー

- HP 40（最大40）。
- 休憩マス：HP を最大HPの30%回復（切り捨て）。

### 戦闘（仕様書 第6章の一部）

- 1ラウンドの手順：予告 → ダイスを0〜2個選ぶ → 振る → 各出目を攻撃か防御に割り振る → 攻撃の解決 → 敵の行動 → ラウンド終了（防御値を0に戻す）。
- 敵の「防御」の予告は、予告した時点で敵の防御値になる。
- 受けるダメージ = max(0, 敵の攻撃値 − 防御値)。攻撃も同じく敵の防御値を先に削る。
- 状態異常は「筋力」だけ実装する（攻撃値の合計に1回だけ加算）。
- 使用可能が1個しかないときは、それを振った時点でリフレッシュが起き、同じラウンドでもう1個選べる。
- 0個を選ぶ「パス」もできる。

### 敵（2種類＋ボス）

| 敵 | HP | 行動パターン（繰り返し） |
| --- | --- | --- |
| スライム | 12 | 攻撃5 → 攻撃5 → 防御4 |
| 小鬼 | 15 | 強化（筋力+1）→ 攻撃6 → 攻撃6 |
| ゴールの番人（ボス） | 40 | 攻撃8 → 防御6 → 強化（筋力+2）→ 攻撃10 |

- 戦闘マスではスライムか小鬼を半々で出す。
- 報酬はなし（フェーズ0ではダイスもゴールドも増えない）。

### 画面

- **マップ画面**：20マスを横一列に並べる。マスは色付きの四角＋文字（空／戦／休／ボス）。自分の位置を表示。下にポーチのダイスを並べ、使用済みは暗くする。
- **止まりうるマスの表示**：ダイスにマウスを乗せると、そのダイスで止まりうるマスを光らせ、確率（%）を表示する。これは仕様の中心なので必ず作る。
- **戦闘画面**：敵の HP・防御値・筋力・予告、自分の HP・防御値。ダイスを選んで「振る」、出目ごとに「攻撃」「防御」を選ぶボタン、「決定」「パス」ボタン。割り振り中は「与えるダメージ／受けるダメージ」の予測を表示する。
- **結果画面**：クリアかゲームオーバーか、かかったターン数、もう一度遊ぶボタン（新しいシード）。

### 遊んだ記録（検証用）

1プレイごとに次を `Application.persistentDataPath` に CSV で追記する。合格条件の判断に使う。

- シード、結果（クリア／ゲームオーバー）、総ターン数、残りHP
- 移動のたびに：そのとき使用可能だったダイスの数と種類、選んだダイス、出目
- 戦闘のたびに：ラウンド数、使ったダイス、受けたダメージ

## テストで確かめること（EditMode）

- リフレッシュ：最後の1個を使った瞬間に全部が使用可能に戻る。
- 戦闘のダイスは戦闘後も使用済みのまま残る。
- ダメージ計算：敵が攻撃8、盾の代わりに「4を防御、5を攻撃」→ 敵に5、自分に4ダメージ。「両方攻撃」→ 敵に9、自分に8ダメージ。
- 敵の防御の予告が、攻撃の解決より前に効く。
- 止まりうるマスの確率：普通の賽でマス0から→マス1〜6が各1/6。マス17から→マス18と19が各1/6、ゴール（20）が4/6。
- 盤面生成：同じシードなら同じ盤面になる。配置ルールを守っている。

## 作る順番

1. フォルダ構成とアセンブリ定義、テスト用アセンブリを作る。
2. ダイス・ポーチ・リフレッシュのロジックとテスト。
3. 盤面の生成と、止まりうるマスの計算、そのテスト。
4. 戦闘のロジック（BattleResolver と敵の行動パターン）とテスト。
5. マップ画面（シーンの組み立ては Editor スクリプトか、手順の説明で）。
6. 戦闘画面と結果画面、画面の切り替え。
7. 遊んだ記録の CSV 出力。

各ステップの終わりに、動作の確かめ方を説明して止まること。
